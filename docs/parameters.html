CRISPR Pipeline parameters

Pipeline parameters for single-cell Perturb-seq CRISPR screen processing, guide assignment, inference, and optional evaluation outputs.

Define the input samplesheet and output directory.

Parameter Description Type Default Required Hidden

 ['string', 'null'] True
outdir Directory where final pipeline outputs are published. string ./pipeline_outputs

Assay and library options

Options describing the assay design, sequencing chemistry, and barcode handling.

Parameter Description Type Default Required Hidden
ENABLE_DATA_HASHING Enable the hashing branch of the workflow.
HelpWhen true, the workflow expects hash modality rows in the samplesheet, runs hashing mapping, filtering, demultiplexing, and uses the hashing dashboard path.
 boolean False
ENABLE_SCRUBLET Run Scrublet doublet detection before guide assignment in non-hashing workflows. boolean False
is_10x3v3 Use 10x Genomics 3' v3 feature-barcode chemistry for guide or hashing mapping, depending on whether hashing is enabled.
HelpThis parameter only changes feature-barcode modalities; RNA mapping always derives chemistry from the RNA seqspec. Case 1: when ENABLE_DATA_HASHING = false and is_10x3v3 = true, mappingGuide uses CHEM=10XV3 with kb --workflow kite:10xFB instead of deriving guide chemistry from the guide seqspec. Case 2: when ENABLE_DATA_HASHING = true and is_10x3v3 = true, mappingGuide remains seqspec-driven, mappingscRNA remains seqspec-driven, and mappingHashing uses CHEM=10XV3 with kb --workflow kite:10xFB. This second case matches the PR #78 hashing/HTO special case for 10x 3' v3 HTO datasets where barcode replacement/translation may be needed so hashing, RNA, and guide barcodes match downstream. When is_10x3v3 = false, guide and hash mapping both derive chemistry from their seqspecs.
 boolean True
reverse_complement_guides Reverse-complement guide spacer sequences while building the guide reference. boolean False
spacer_tag Recommended 12 bp sequence immediately upstream of the guide spacer.
HelpUse this when the guide spacer is preceded by a constant adapter/tag sequence. A 12 bp tag is recommended because it is usually specific enough to anchor the guide read while still tolerating normal read quality. When provided, mappingGuide preserves the guide read ID from the seqspec but resets the guide feature start/end to 0,0 so kb can search the whole guide read for the tagged spacer. Set null or an empty string to rely strictly on the feature coordinates encoded in the guide seqspec.
 ['string', 'null'] GAGTACATGGGG
scrna_workflow kb count workflow used for scRNA mapping. (accepted: standard|nac)
Helpstandard runs regular mature transcript counting against the selected transcriptome index. nac runs nascent-aware counting by passing kb --workflow nac with both the cDNA reference and nascent reference, allowing the RNA modality to capture nascent/unspliced signal in addition to mature transcript signal. Use nac only when the selected reference bundle includes the nascent index expected by the pipeline.
 string standard
use_multimapping Pass kb count multimapping mode to scRNA mapping and preserve that setting during AnnData concatenation. boolean False
replace_barcodes Enable barcode replacement during RNA and guide mapping.
HelpThis is the CC-Perturb-seq barcode correction strategy. When true, RNA and guide mapping pass bc_replacement_file to kb count with -r so barcodes can be translated to a shared/corrected barcode namespace before modality overlap. Downstream concatenation then reads counts_unfiltered_modified outputs. Leave false for standard 10x-style data where RNA and guide barcodes already match.
 boolean False
bc_replacement_file Barcode replacement table used when replace_barcodes is true. string
DUAL_GUIDE Enable dual-guide-aware aggregation when concatenating guide-assigned MuData. boolean False
Multiplicity_of_infection Expected CRISPR screen multiplicity of infection. (accepted: high|low)
HelpStored in guide.uns['moi'] during MuData creation. If set to high, downstream guide assignment and perturbation inference are allowed to represent cells with multiple guide assignments, which is appropriate for high-MOI screens. If set to low, the pipeline records a low-MOI design where most cells are expected to carry zero or one perturbation; this affects how guide assignment and interpretation of perturbation-level tests should be handled. If a non high/low value is provided, create_mdata.py estimates high versus low from the average number of detected guides per cell.
 string high

Quality control options

Cell, gene, and barcode filtering options used during preprocessing and QC reporting.

Parameter Description Type Default Required Hidden
QC_min_genes_per_cell Minimum detected genes required to keep a cell when QC_barcode_filter is none.
HelpA gene is considered present in a cell when its count is greater than zero in the RNA AnnData matrix. This parameter is passed to scanpy.pp.filter_cells(min_genes=...) and is only active when QC_barcode_filter = 'none'. When knee or knee2 filtering is enabled, total RNA UMI depth selects cells first and the min-genes cell filter is skipped.
 integer 800
QC_min_cells_per_gene Minimum retained-cell fraction required to keep a gene.
HelpMust be in [0, 1). Zero retains every gene detected in at least one cell; use a small fraction for permissive TAP-seq retention.
 number 0.05
TAPSEQ_QC_MODE Use TAP-seq gene-retention QC.
HelpWhen enabled, preprocessing removes only genes undetected in every retained cell instead of applying the standard 10-cell prefilter. Use a small QC_min_cells_per_gene fraction such as 0.000001 to retain all observed TAP-seq genes.
 boolean false
QC_pct_mito Maximum mitochondrial read percentage allowed per cell. number 15
QC_batch_col Observation metadata column used as the batch label in additional QC plots. string batch
QC_barcode_filter RNA barcode filtering strategy based on total cell RNA UMI depth. (accepted: none|knee|knee2)
HelpThe preprocessing script sums RNA UMIs per cell, sorts barcodes from highest to lowest total_gene_umis, plots log1p(total_gene_umis) versus barcode rank, and estimates up to two knees. 'knee' uses the first/basic knee: the barcode-rank point with maximum distance from the line joining the highest-UMI and lowest-UMI barcodes. This is more permissive and keeps cells with total_gene_umis greater than or equal to the UMI count at that first knee. 'knee2' first restricts the curve to the high-UMI segment before knee1 and then finds a second/advanced knee using spline curvature; this is stricter and is intended to remove additional low-quality or background barcodes inside the initially retained population. 'none' disables UMI-knee filtering and instead applies QC_min_genes_per_cell. If the requested knee cannot be determined, barcode filtering is skipped with a log message; preprocessing then continues, and because QC_barcode_filter is not 'none', the min-genes cell filter is also skipped. Cells tied at the selected UMI threshold are retained.
 string knee2
